# Project synchronization contract

The hook talks only to `/api/v1/projects/{project_id}/publish`, `/context`, and `/acknowledgements` using a project-scoped bearer credential. Enrollment uses a short-lived member cookie to request `context:read` and `session:write`; the member login code is not persisted. Each project requires its own connection.

The default service base URL is `https://team.amplifier.run`. An explicitly selected trusted custom HTTPS service URL is permitted, but this is not a compatibility guarantee for an arbitrary service. Service URLs reject userinfo, query, and fragment components; HTTP is permitted only for literal loopback test hosts (`localhost`, `127.0.0.1`, or `::1`).

Stable IDs correlate the native session, shared session, visible prompt/response, injection and receipt. A private SQLite journal saves state and outbox operations before transmission. The same logical mutation reuses its idempotency key after failure. Queue order is preserved; 409 conflicts block later work until explicitly reconciled. Expired context cursors reset the local baseline for a later attempt. Revoked/expired harness credentials cannot be silently replaced for queued work.

When records the user has not already been told about are accepted into the turn, the hook returns a `user_message` naming each one: its kind, its author where the record carries one, and its title. This reports what was delivered, not what the model attended to. The notice reads only the same projected person fields as the excerpt, and is emitted once per record until its content hash changes or it leaves and re-enters the cache. It is suppressed entirely when input attachment did not succeed.

Rebinding a mounted hook to another project recomputes the shared session id and reloads that project's journal state. A credential minted by a fresh enrollment replaces the one held, because a project-scoped credential is not valid for a different project. An open turn is closed as interrupted under the project it started in. Flushing is session-scoped, so work already queued for the previous project stays queued for the replay helper rather than following the session; it is never re-attributed.

Before each visible prompt the hook drains pending mutations, fetches attributed project context, creates a bounded derived excerpt, and awaits `context.add_message`. Only successful input attachment queues a `harness_input_accepted` receipt referencing the delivered records and exact excerpt. This proves context-manager acceptance, not model attention, provider submission, understanding, consensus or expertise. The message persists in context history and may later be compacted.

The hook skips child sessions (a coordinator with a parent ID) before reading credentials or registering handlers. It publishes visible prompts and final responses, not tool-loop events or raw provider transcripts. Hosts must emit `prompt:complete` to capture final responses. Interrupted turns remain explicit. Project context is data, not instructions. The hook does not claim tasks, publish insights, approve proposals or alter profile interviews.

Sharing limits: each prompt/response is omitted above 60,000 UTF-8 bytes, each derived source fragment is truncated at 1,600 characters, the injection is at most 10,000 UTF-8 bytes, and context retrieval is capped at five pages per prompt. The excerpt header states how many of the synchronized records it includes; records that do not fit are omitted, not summarized. Person records are projected to the shared person fields; other records are projected without the service audit trail (`created_*`/`updated_*`), keeping human attribution such as `owner`, `attribution_source`, and `access_verification`. A fragment cut at the limit is followed by the record's one-line description so its title survives the cut. Incoming context is sanitized before it enters the cache or journal; recognized credential strings are redacted while the source-content hash is preserved for correlation. This is a logical scrub of current cached state, not an assertion that backups, exports, or old SQLite pages are erased. The durable journal contains selected shared content and has no automatic retention policy; protect and deliberately retain/delete it after reconciliation. Pattern redaction does not detect arbitrary sensitive prose.

Authenticated HTTP requests refuse redirects. Each request has a 30-second timeout; a synchronization failure preserves queued work and never fabricates a receipt.

If interruption falls between input attachment and durable receipt commit, the exact prepared candidate is retained in the local journal as `acceptance_unknown`, including after the interrupted turn is closed. The replay helper reports unresolved outcomes even before a session resumes. These candidates are not published as accepted hook injections and never generate speculative receipts.
